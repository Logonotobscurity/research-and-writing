## 4. Cross-phase patterns

1. Understand before prescribing.
2. Translate research into architecture, workflow, and implementation.
3. Treat permissions, consent, approvals, and auditability as system concerns.
4. Preserve context through notebooks, repository documents, and memory systems.
5. Distinguish a plan, prompt, mock-up, and repository from a tested working product.
6. Keep evidence categories visible and avoid inventing completion or capability.

## 5. How to read the phase map

Phases overlap; they are not exclusive time periods. Many projects run in parallel and return in later conversations. When a later discussion clarifies an earlier one, preserve both the initial interpretation and the correction. The purpose is to show how understanding evolved, not to force a perfectly linear story.
