# 05 — Integrated Personality and Working Model

## Consolidated description

**Research-led systems building** is the best current description of the user's recurring intellectual and working orientation.

This phrase intentionally combines both dimensions:
- **Research-led:** investigation helps reveal how a system works, why a problem is complex, what is missing, and what should be attempted.
- **Systems building:** the user turns that understanding into architecture, mechanisms, working products, and integrated capabilities.

It is a practical description, not a clinical or psychometric personality classification.

## The iterative operating cycle

1. **Investigate** — enter an unfamiliar problem space with curiosity; examine evidence, mechanisms, assumptions, and context.
2. **Understand complexity** — map causes, dependencies, constraints, interactions, and failure points.
3. **Discover** — identify overlooked gaps, opportunities, and possibilities.
4. **Define and prioritise** — decide what problem should be addressed and what outcome matters.
5. **Architect** — design the structures, interfaces, policies, workflows, and mechanisms needed.
6. **Build** — implement a functioning system that addresses the problem.
7. **Integrate** — connect technologies, platforms, agents, data, and infrastructure into coordinated capabilities.
8. **Validate** — test the system against real requirements and observable outcomes.
9. **Expand and learn** — identify new opportunities and unresolved issues; feed them back into investigation.

The cycle is iterative, not strictly linear. Building can expose a new question; integration can reveal a hidden dependency; validation can change the original problem definition.

## A compact model

**Investigate → Understand → Discover → Define → Architect → Build → Integrate → Validate → Expand**

The sequence describes a recurring loop rather than a fixed personality type.

## Five complementary dimensions

| Dimension | Role in the working pattern |
|---|---|
| Investigative curiosity | Motivates exploration of unfamiliar mechanisms and systems. |
| Research and discovery | Reveals gaps, opportunities, and better problem definitions. |
| Complex problem-solving | Makes sense of difficult interactions and resolves them. |
| Architecture and building | Turns understanding into operational systems. |
| Integration and expansion | Combines capabilities and identifies new possibilities. |

## Implications for collaboration

When supporting the user on a research or engineering task:
- Do not rush to implementation before the problem and system are understood.
- Do not let investigation become detached from the practical question of what can be built or tested.
- Explain why a problem is complex, not just how to solve it.
- Identify mechanisms, dependencies, trade-offs, and overlooked opportunities.
- Translate findings into architecture, implementation plans, and validation criteria.
- Treat integration as a first-class design concern.
- Distinguish evidence from inference and hypotheses.
- Preserve the path from research question to practical system and measured outcome.

## Current conclusion

The earlier systems-builder interpretation remains valid. The newer investigative insight explains more fully how the user discovers and defines what to build. The integrated model is stronger because it accounts for both the origin of the work and its practical realisation.
