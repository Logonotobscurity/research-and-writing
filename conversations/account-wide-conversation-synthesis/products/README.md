This folder preserves the product-specific parts of the account's conversation history. Each dossier is intentionally bounded: it records the user problem, intended product, differentiating mechanism, known architecture, status claims, evidence gaps, and next research or engineering questions.

These documents are not substitutes for the actual repositories or current source-of-truth specifications. They are navigation and context records.

## Cross-product rules

- A product's source-of-truth repository and current branch take precedence over this summary.
- A README or specification describes intent; code and tests are needed to establish implementation.
- A merged pull request is not a guarantee that a complete user journey works.
- A reported user count, metric, or outcome remains user-reported until independently substantiated.
- A prototype is not production evidence.
- A private competitor or reference product should not be exposed in public positioning unless there is an explicit, legitimate reason.
- Keep user consent, authority, privacy, provenance, and verification explicit where the product can affect people or external systems.

## Maintenance

When a product changes materially, add a dated status note or a new dossier revision. Do not silently replace a previous known gap with a claim of completion. Record what source was inspected and what tests were run.
