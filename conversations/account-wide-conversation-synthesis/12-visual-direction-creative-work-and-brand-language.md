# 12 — Visual Direction, Creative Work, and Brand Language

## 1. Scope

The user's visual and creative conversations cover business identity, product interfaces, visual prompts, poster concepts, and distinct aesthetic directions for different products.

The archive should not force every product into one visual style. A shared brand system may provide coherence, but individual products can require different visual languages.

## 3. Product-specific visual directions

### GigPilot

The user has requested a Basquiat-inspired direction for GigPilot. That direction should be understood as an expressive, energetic visual reference, not as an instruction to copy a specific artwork or reproduce protected material.

A product design should still support:
- Clear hierarchy.
- Legible job and opportunity information.
- Trust signals.
- Accessible interaction.
- Useful status and workflow state.
- A consistent visual system across mobile and desktop.

The visual direction should serve the product's purpose rather than obscure the information users need to make decisions.

### LOG_ON and fintech/editorial interfaces

The VisionOS-card and fintech-editorial preferences suggest:
- Clear spatial hierarchy.
- Strong typography.
- Restrained use of color.
- Distinct information surfaces.
- High contrast and accessible text.
- Meaningful motion rather than decorative animation.
- Interfaces that present complex systems as understandable states.

### Creative poster and wallpaper work

## 4. Prompt-writing standards for visual generation

A useful visual prompt should define:
- Intended medium and aspect ratio.
- Main subject and composition.
- Visual hierarchy.
- Palette and material.
- Texture and mark-making.
- Lighting and contrast.
- Typography requirements.
- What must remain legible.
- What must be excluded.
- Whether the output is a concept, poster, product mockup, or production asset.

When exact text must appear in an image, inspect the final generated output. Image generation may distort typography; critical wording should be corrected in a design tool where exact typesetting is required.

## 5. Visual design and product behaviour

A polished interface should not conceal missing functionality. The user has repeatedly emphasized that product audits should identify whether a UI is backed by real state and real workflow behaviour.

Design review should therefore ask:
- Does each component represent a real product state?
- Are loading, error, empty, disabled, and approval states defined?
- Can a user understand what has happened?
- Does the design expose relevant uncertainty?
- Is the visual hierarchy consistent with the risk and importance of the action?
- Can the user recover from an error?
- Does responsive behaviour preserve the essential workflow?

## 6. Accessibility and implementation

The design process should include:
- Contrast checks.
- Keyboard navigation.
- Clear focus states.
- Screen-reader labels.
- Reduced-motion support.
- Responsive layouts.
- Touch target sizing.
- Readable line lengths.
- Error messages adjacent to affected controls.
- Consistent semantic hierarchy.

Visual effects should not replace semantic structure or working interactions.

## 8. Current working conclusion

Visual direction is a product and communication decision, not merely decoration. It should make information and state understandable, preserve accessibility, and strengthen the product's identity without hiding the underlying workflow or its limitations.
